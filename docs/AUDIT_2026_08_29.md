## B. Findings DOCUMENTED, deliberately not changed (need owner decision or are dead paths)

1. **`_commit_explicit_memory` reads a deep-copied-away field** (`head["memory_candidates"]` never exists on the caller's compact head). Harmless today because the compact spec doesn't request memory candidates — in-session memory flows through the deterministic extractors (Aiva-reply + user-utterance) → `store.commit(immediate=True)`. If the head spec ever grows a memory field, this must read the updater-mutated head.
2. **`GeminiLiveSTT.transcribe_stream` (providers/stt_gemini_live.py) is dead code with a latent bug:** its Groq fallback re-iterates an already-consumed async generator (would yield empty). Not on any live path (router has its own class). Fix when the Gemini-Live-primary comparison run happens.
3. **TTS fallback timeout (7s) vs LLM 429 rotation (65s cooldown):** if every key is exhausted mid-rotation, the first-audio timeout fires and EdgeTTS may speak with empty text → silent turn with `fallback_reason` logged. Acceptable: quota exhaustion is loud in console + events; a longer timeout would add latency to every genuine Fish failure.
4. **`mem` field absent from the compact perception spec** (by earlier owner-approved rollback after 80% PARSE-FAIL evidence). Memory capture = deterministic extractors; revisit only with new evidence.
5. **Known residuals carried forward:** barge-in stop latency 2–3s (Phase 7), Fish Audio TTFA 0.6–2.4s (owner decision on faster tiers / ElevenLabs Flash pending), response-quality tuning against real fused-brain sessions (all previous "quality" evidence except 08-28-afternoon came from the legacy brain).
